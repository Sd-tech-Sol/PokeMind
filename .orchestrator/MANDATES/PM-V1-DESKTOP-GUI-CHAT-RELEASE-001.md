## Chatbot : fournisseur par défaut Codex CLI App Server (architecture vérifiée)
- Intégrer au **processus Codex présent sur le PC** via **`codex app-server` en transport `stdio` local**, protocole JSON-RPC, handshake `initialize` puis `initialized`, `thread/start`/`thread/resume`, `turn/start`, notifications de streaming `item/agentMessage/delta`, fin de tour `turn/completed`, annulation `turn/interrupt` ; app-server lancé comme **processus enfant géré** (pipes séparés, lecture asynchrone, nettoyage et timeout, diagnostics de version/install/auth). Générer et utiliser les schémas de **la version Codex réellement installée** lorsque possible. Éviter WebSocket expérimental, serveur exposé sur LAN, parsing ANSI du TUI et bricolage `codex --yolo`.
- **Alternative acceptable à justifier** : si app-server exact est indisponible sur ce PC, `codex exec --json` non interactif avec `resume` et évènements JSONL est un mode dégradé temporaire explicitement signalé, **pas** un faux multi-tour persistant. Ne pas faire passer un appel OpenAI REST pour « session Codex terminal ». La session Codex est persistée/identifiée localement et associée à l'historique du chat PokeMind; reprise fiable après fermeture et changement de moteur.
- **Autres fournisseurs** au même contrat `ProviderAdapter` (capabilities `available, start/resume, stream, cancel, close, health`) :
  - **Claude Code local CLI/Agent SDK** : si déjà installé/connecté, utiliser `claude -p --output-format stream-json` et sa reprise officielle/session, ou son SDK officiel. Pas besoin d'une nouvelle clé supposée. Si absent, état « non installé » et instructions, pas de crash.
  - **Ollama local** : via `http://127.0.0.1:11434/api/chat`, liste de modèles réellement installés, streaming, historique local, annulation; refuser hôtes distants non configurés explicitement, ne télécharger aucun modèle silencieusement. Option offline et limite mémoire/VRAM documentées; ne jamais présumer qu'un LLM tourne sur le PC.
  - Possibilité d'ajouter d'autres fournisseurs plus tard **sans refaire l'UI ni les services PokeMind**. Si Codex indisponible/offline, **l'interface de données PokeMind continue de fonctionner**; moteur de substitution uniquement après choix explicite de l'utilisateur.
- Le chatbot doit **connaître PokeMind** par une **couche d'outils/consultation de services déjà existants**, en lecture seule par défaut (résumés analytiques, deck exact, cartes, méta, Memory), avec provenance et statut de fraîcheur; limite taille/contexte, contrôle d'entrées privées. Une question « pourquoi ai-je perdu contre X » doit produire les éléments W/L/n et hypothèses du vrai snapshot, pas halluciner des matchs ni répondre sans données. Prompt injection des journaux, pages et cartes traité comme données non fiables. Ne pas accorder à Codex l'exécution de commandes système/écriture arbitraire depuis le chat simplement parce que Codex peut coder.
- **Données et vie privée** : Codex/Claude peuvent envoyer prompt + contexte au fournisseur cloud selon leurs produits; **afficher clairement cette distinction** face à Ollama local avant la première utilisation cloud. Les journaux bruts/images/identifiants ne sont jamais injectés par défaut. Contextes cloud bornés au strict nécessaire avec paramètres de partage explicites, aucune publication GitHub; jamais exposer tokens d'auth, secrets, `~/.codex`, `~/.claude` ou chemins dans logs. Pour la réponse personnalisée, faire apparaître clairement si seuls des agrégats anonymisés sont transmis, et proposer une préférence locale de confidentialité mémorisée. Pas de promesse mensongère « 100 % offline » en mode Codex/Claude.
- **Sécurité processus/outils** : limiter cwd, sandbox/permissions, aucun `--yolo` dans l'app, aucun shell à partir de messages UI; si un agent propose une écriture ou une action destructive, afficher une approbation explicite avec une action compréhensible. Le mode par défaut est questions/conseils **read-only** avec les API PokeMind. Plusieurs messages, bouton Stop, sortie/reconnexion, erreurs fournisseur et timeout doivent fonctionner réellement.
