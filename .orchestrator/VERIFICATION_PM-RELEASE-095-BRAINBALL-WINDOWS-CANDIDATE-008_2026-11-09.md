## Vérification indépendante de l'incident
1. `src/pokemind/demo.py:run_demo` crée une base `synthetic.sqlite3` et fichiers tests sous `<projet>/data/local/demo-runs/i-demo-*`. Le helper CLI fournit explicitement `--db <workspace>/synthetic.sqlite3` à presque tous les sous-processus. Il passe `POKEMIND_ROOT=<projet>` mais **PAS** `POKEMIND_DATA_ROOT=<workspace>`.
2. `src/pokemind/cli.py` résout `data_location.cli_root(project)`. `data_location.py:_recorded` peut sélectionner un `POKEMIND_DATA_ROOT` hérité, ou un `location.json` qui pointe vers un dossier externe accepté, sinon le répertoire projet. Le chemin choisi pour les exports `deck export` est `<racine active>/data/local/decks` si la base explicite n'est pas dans les `demo-runs` de **cette racine active**. Ainsi même avec la base SQLite fictive, l'export peut aller ailleurs que `workspace`.
3. `demo.py` appelle `run("deck","export","synthetic")` puis seulement **après** contrôle si `text_path` est sous `workspace`. L'erreur renvoyée signifie que le fichier exporté est hors du workspace, et non nécessairement que la racine est celle du propriétaire.
4. `src/pokemind/deck_exports.py:export_confirmed_deck` fabrique un deck `synthetic` version 2 et écrit typiquement **deux fichiers distincts** (`synthetic_v2.txt` et `synthetic_v2.json`) dans `decks/import_ready/`, en utilisant `_atomic_write_new` : fichier temporaire puis `os.link`, **pas d'écrasement d'un fichier existant**, pas de suppression d'autres dossiers. Si la commande a produit un `text_path` et que l'assertion suivante a échoué, l'export a normalement réussi, donc **deux fichiers fictifs supplémentaires sont plausibles** dans la racine active. Leurs chemins réels ne sont pas établis; ne pas présumer lesquels ni les supprimer automatiquement.
5. Les importations/recherches précédant ce point utilisent une base de données explicitement éphémère. Aucun accès Internet n'est nécessaire pour cet export. La relecture statique **réduit fortement** la portée plausible de l'incident à la création de sorties synthétiques hors du workspace; elle ne fournit pas une attestation d'intégrité de l'arbre propriétaire. Aucun journal de commande détaillé ni vérification en lecture seule des deux fichiers n'a été fourni.

**Action de sécurité :** bloquer le candidat 008 et corriger le routage dans le code source avant de construire un autre binaire. Pour toute vérification dans une vraie racine propriétaire, exiger une autorisation distincte et un protocole **lecture seule** limité aux chemins/présence/métadonnées des deux fichiers attendus; ne pas ouvrir le contenu des decks existants, ni écrire/supprimer/restaurer sans GO.
